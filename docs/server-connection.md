# Connect a server and share a list

In Android, tap the sharing icon on the list, or open **Settings > Shared lists**.
Scan the server QR or paste its HTTPS link, then choose **Connect this server**.
Open the browser sign-in, compare every group of the displayed device code and
approve. Return to Usuals; it detects approval automatically. Setup can resume
after switching apps or restarting the phone. An expired attempt can be cancelled
and started again.

On the web, **Account > Connect a server** shows the instance link and QR. The
instance address is already selected by visiting its website. On the same phone,
the connection link can open the installed Usuals app. Self-hosted domains use the
QR, paste or explicit app handoff without requiring a centrally hosted service.

For your first shared list, create a household, save its recovery file and secret
separately and verify them. An admitted account can create a household without an
operator setup code. When started from the list’s sharing icon, its preview resumes automatically
after household creation. Otherwise choose **Share a local list** and select the
source. Review whether to include history; it starts off. Interrupted shares
reuse the prepared copy and its history choice instead of creating another copy. Usuals keeps the original local copy and
selects the new shared copy.

To invite someone, open **Connect a phone** or **Invite someone**. They open or
scan the invitation and confirm its server. Open **Review requests**, compare
every group of the code with their device and approve only when they match.
A computer camera and fingerprint typing are unnecessary. Verification QR remains
available if preferred. Signing in alone never grants household keys.

Server account services can be used for AI while your lists remain local. In
Android's connection panel, expand **Use server AI**, review the provider and
processing destination, then enable it. In the web account screen use **Server
AI** to choose the server default or an approved personal provider. Imports always
require an explicit model action and a review before adding items.

Account connections expire after 30 days. Disconnecting account services preserves
existing household shopping work. Disconnecting offline removes the local token;
use **Account > Connected phones** in the browser to revoke that connection
if immediate remote revocation is needed. Existing direct native provider settings are retained and no saved
Keystore key is automatically uploaded to the server.

The legacy manual setup path remains available for older installations. A server
must support connection protocol 1 and migration 005 for the new account flow.
